Business Insights Agent Architecture

An agent that answers "what" and "why" questions about a fictional Australian motor and home insurer's claims data, searches its internal policies, and reviews claim files for compliance. Every finding is backed by the SQL or the policy clause that produced it.

Phases 0–6 done 631 offline tests pass US$28.82 of US$32 spent (A$50 cap) Phase 7 next: demo polish and push to GitHub

How a question flows

The app fixes the user's role, starts the MCP servers for that role, and runs the LangGraph loop until Claude writes a structured report. Nothing the model calls can write to data; actions wait for a person.

Guardrails in code

Access

  • The app sets the role; the user can't change it in conversation.
  • Restricted roles query a warehouse copy with no personal data.
  • One read-only SELECT per query; no files, no extensions, time and size caps.

Trust

  • "Agreed metric" labels are set by code from the tool calls.
  • Policy citations are checked against the clauses the tools returned.
  • Key numbers are checked against their own query; rounded ones are marked.
  • Claim notes are treated as data, so an injected instruction is ignored.

Actions and cost

  • The model has no tool that writes; a person approves each action.
  • Caps: 24 tool calls and US$0.50 per question, US$0.35 per review.
  • The spend ledger refuses calls past US$32.
